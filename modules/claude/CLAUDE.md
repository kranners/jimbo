# Personal preferences

Always prefer the simplest and narrowest solution that fits the actual case. No
additional complexity from generalising.

Everything should be as simple as possible. If code isn't simple, something is
wrong. Step back and ask to evaluate the approach, suggest alternatives.

Feature branches are merged into `develop`. HEAD branch if there is no
`develop`.

I manage worktrees myself. If asked making edits, do not use worktrees, edit
the working copy.
