## What this is

- `jimbo`, NixOS PC, `x86_64-linux`, dual booting a Windows install Nix does not manage
- `piggys-MBP`, MacBook via nix-darwin, `aarch64-darwin`

- `spike`, always-on NixOS box, `x86_64-linux`

- `nuc`, a spare Intel NUC as spike's worker box, NixOS, `x86_64-linux`, not installed yet, every role it will take off until switched on (`modules/hosts/nuc/README.md`)

## Commands

```sh
just          # rebuild + switch the current host (runs `git add .` first, then nh)
just check    # nix flake check --show-trace
```

`just` stages everything before building because flakes only see git-tracked files.

## Workflow

The landing check is `just check`.
The weekly `flake-update-*` branches are the exception: they land through the pull request the bot opens.
CI runs `nix flake check` on every push to every branch (`.github/workflows/test.yml`).
The weekly update bumps every input.
It also runs `modules/browser/update-extensions.sh`, which pins each browser extension in `modules/browser/extensions.nix` to the release the Chrome Web Store serves, since the store serves only the newest one and an older pin fails the build.
The flake check `browser-extensions` fetches every pinned extension, so CI's cachix-action daemon pushes each one to the `kranners` cache as it is built, from which every host substitutes it after the store has moved on, so a pin that lags the store still builds.
That cache is public, so CI pushes only what it builds and never a `-source` path, which keeps the private input `butler`'s source out of it, as its store path follows from the public `flake.lock`.
`.claude/worktrees/` is gitignored so the `git add .` in `just` never stages a worktree.

A claude.ai cloud session's proxy refuses nix's `github:` tarball downloads and has no SSH key, so check there, after `add_repo` of `kranners/butler`, with every locked `github:` input and the `git+ssh` input `butler` fetched over HTTPS git instead, where `browser-extensions` fails on any pin that lags the store:

```sh
overrides=$(jq -r '.nodes as $n | def walk($node; $path): ($n[$node].inputs // {}) | to_entries[] | select(.value | type == "string") | ($path + [.key]) as $p | ($n[.value].locked | if .type == "github" then "--override-input \($p | join("/")) git+https://github.com/\(.owner)/\(.repo)?rev=\(.rev)&shallow=1" elif .type == "git" and (.url | startswith("ssh://git@github.com/")) then "--override-input \($p | join("/")) git+https://github.com/\(.url | ltrimstr("ssh://git@github.com/"))?rev=\(.rev)&shallow=1" else empty end), walk(.value; $p); walk(.root; [])' flake.lock)
nix --extra-experimental-features 'nix-command flakes' flake check --keep-going $overrides
```

Update this file, or `modules/hosts/spike/CLAUDE.md`, in the same branch as any change that makes it wrong.
It keeps one sentence per line, so git merges edits from two branches sentence by sentence.
Work-only configuration uses neutral names such as `work` and "the work repositories", and anything naming the work itself, its repositories, addresses or people, lives in `kranners/butler-memory` rather than here.

## Architecture

Instead of writing `nixosConfigurations`/`darwinConfigurations` directly, `flake.nix` runs `lib.evalModules` over `./modules` once per host and merges the results with `lib.recursiveUpdate`.

Every directory under `modules/` is a config module that contributes to one or more of these options (defined in `modules/default.nix`):

- `sharedSystemModule` / `sharedHomeModule` — both platforms
- `nixosSystemModule` / `nixosHomeModule` — Linux only
- `darwinSystemModule` / `darwinHomeModule` — macOS only

`modules/default.nix` assembles these into the real `nixosConfigurations`/`darwinConfigurations` (guarded by platform, parsed from `host.system`).
`modules/home/default.nix` wires the home modules into home-manager for `host.username`.

`modules/default.nix` imports its first list of modules on every host, its second list only when `host.desktop` is true, and a third list, after the desktop one, only when `host.kiosk` is true, for a machine that runs as an appliance instead of a desktop.

**To add configuration:** create `modules/<name>/default.nix` returning an attrset with the relevant option keys above, and add `./<name>` to the `imports` list in `modules/default.nix`, in the `host.desktop` list if it only makes sense on a machine with a screen, or the `host.kiosk` list if it only makes sense on an appliance.

Modules receive `inputs` (flake inputs) and `host` (`{ system, hostname, username, desktop, kiosk }`) via `specialArgs`, in addition to the usual `pkgs`/`lib`/`config`.
Because `host` is a `specialArg`, `imports` may depend on it, whereas depending on `config` there recurses infinitely.

### Hosts

`modules/hosts/<host>/` holds facts about one machine only: hardware, bootloader, hostname, state versions.
Only the directory named exactly `host.hostname` is imported, so it applies to that machine alone.

`modules/kanban-runner` runs a kanban runner on `pilot` and `piggys-MBP`, as the launchd agent `kanban-runner`, logging to `~/Library/Logs/kanban-runner.log`, and on `jimbo`'s NixOS, as the user unit `kanban-runner`, so the board can start Claude Code sessions there, named `pilot`, `piggys-mbp` and `jimbo`.
On `pilot` it waits, checking every 5 minutes, while pilot's own board, the launchd agent `kanban`, is loaded, so it starts only once the board has moved to spike and that agent is unloaded.
Each fetches the board's own `/runner.js` from `https://kanban.spike.cute.engineer` with its token and runs it with Node against that hub, keeping the last copy it fetched for when the hub is away.
The board names the `runner.js` it serves as each runner registers, and a runner on older code replaces its copy and exits once none of its sessions is live, so launchd or systemd starts it on the board's code.
Each session a runner starts gets the board's doc tools, the `kanban` MCP server, which reaches the board's docs with the runner's token, since the board moved to spike and none of its sessions runs on its own loopback.
The token is `KANBAN_RUNNER_TOKEN` in `~/.config/kanban/env`, mode 600, the same on `pilot` and each runner, written by hand and never in the repository, and the runner waits, retrying every 5 minutes, until it is there.
`jimbo`'s runner reaches spike only once spike has its WireGuard peer, through `jimboPublicKey`, and runs only while it is booted into NixOS, since its Windows install runs none.
Wherever `cswap` on the runner's `PATH`, which includes `~/.local/bin`, manages two or more Claude accounts, as on `pilot`, the runner starts each session on the one with the most headroom and resumes a session that ends on a usage limit on another, and the board does the same for its own sessions, as kranners/kanban's `docs/design.md` describes under Accounts and failover.

### cswap auto

`modules/cswap-auto` runs `cswap auto --strategy best --threshold 90 --weekly-threshold 95` on `pilot` as the launchd agent `local.cswap-auto` in the gui domain, so cswap reaches the login keychain, logging to `~/.local/state/cswap-auto.log`.
Its `cswapAuto` options set the strategy, both thresholds and cswap's path, by default `~/.local/bin/cswap`, where `modules/claude` has uv install it, and `cswapAuto.enable` is off on `piggys-MBP`.
Its label is the one the plist first made by hand had, which home-manager unloads and overwrites on the first switch, so nothing needs removing by hand.
`cswap auto` moves only the default login, so a session already running in an account's cswap profile stays on it; the kanban board and runners fail such a session over to another account themselves when it hits its limit.

### Speed reading

`modules/speed-read` puts the Raycast script command Speed Read Selection in `~/.config/raycast/scripts` on the Macs, which copies the selection and plays it one word at a time from 500 wpm with agent-rsvp, at twice the Terminal profile's text size, in a Terminal window centred on the screen under the mouse pointer, after waiting for the hotkey's modifiers to be released so its copy keystroke reaches the app as a plain ⌘C.
On every switch it sets the default Terminal profile to close a window when its shell exits cleanly, so quitting the reader closes its window.
Adding that directory under Raycast's Script Commands and giving the command a hotkey are hand steps, since Raycast keeps both in its own database.

### WireGuard

`modules/wireguard` installs the WireGuard app from the App Store on the Macs.
On `pilot` its tunnel `Home network` is spike's peer `pilot`, imported by hand from `~/.config/wireguard/Home network.conf`, which holds its private key and never enters the repo.
`modules/spike-dns` gives each Mac split DNS for spike's WireGuard-only names, one `/etc/resolver/<name>` per name in its `names.nix` pointing at spike's resolver on `10.100.0.1`, so only those names go through the tunnel, its configs keep no `DNS =` line, and a dead spike or a tunnel that is off breaks nothing else.

### Butler's access

`modules/butler-access` lets butler on spike drive both Macs: it turns on Apple's Remote Login with password logins off, and authorizes butler's key from `10.100.0.1` alone, under `restrict` with port forwarding back on and its TCP forwards limited to `127.0.0.1:5900`; the key runs any command as Aaron, so that limit is tidiness, not a boundary.
On every switch it loads the pf anchor `com.apple/butler-access`, which drops Screen Sharing on every interface but loopback, and stops if the anchor's block rule is not loaded, as the launchd daemon `butler-access-pf` loads it at boot and every minute, enabling pf again if anything disabled it, sets `VNCLegacyConnectionsEnabled` and `VNCAlwaysStartOnConsole`, which sends a legacy VNC session to Aaron's console rather than a login window on a virtual display, and starts `com.apple.screensharing`.
The first switch gives Screen Sharing a random 8-character legacy VNC password with `kickstart`, kept in `~/.local/state/butler-access/vnc-password` for butler to read over ssh.
Screen Sharing must also be switched on once by hand in System Settings, General, Sharing, because since macOS 12.1 only that switch or an MDM lets its agent capture the screen and post input; started by `launchctl` alone, it serves a black screen.
It installs Hammerspoon from Homebrew and runs it at login as the LaunchAgent `hammerspoon`, kept alive, with butler's config `~/.config/hammerspoon/init.lua` and `butler.lua`, through its `MJConfigFile` default, so a `~/.hammerspoon` of Aaron's own is never touched.
`butler.lua` serves butler's helper on `127.0.0.1` at the port in `modules/butler-access/helper.nix`, answering only requests carrying the token in `~/.local/state/butler-access/hammerspoon-token`, which home-manager's activation generates once, mode 600, and reloads itself when its config changes.
It acts with Hammerspoon's own Accessibility and Screen & System Audio Recording, which Aaron switches on by hand once per Mac in System Settings, Privacy & Security, and which follow Hammerspoon's Developer ID signature through updates, where a helper built in the Nix store would lose them on every rebuild and a grant to `sshd-keygen-wrapper` would reach every ssh login.
Its user LaunchAgent `butler-keepawake` keeps the Mac awake and unlocked for butler, starting a 40 second `caffeinate -d -i -m -s -u` every 30 seconds, so each overlaps the next and the assertions never lapse, which holds off idle, display and AC system sleep and declares the user active, so the screen saver and display sleep that would lock the screen never start, with no sudo.
Its `butler-keepawake` command, which `mac <host> keepawake [status|on|off]` and `mac <host> sleep` run over ssh, writes `on` or `off` to `~/.local/state/butler-access/keepawake` and restarts the agent, and the Mac's default applies while that file is missing: on for `piggys-MBP`, off for `pilot`, since it would sidestep its employer's lock policy.
On `piggys-MBP` alone, by Aaron's request, `idleLockOff` in `modules/butler-access/default.nix` also turns the screen saver off and its password off in `com.apple.screensaver`, ByHost and user domains, and each switch warns while `sysadminctl -screenLock status` is not off, which only Aaron can change, with `sysadminctl -screenLock off -password -`, so nothing idle locks it; setting `idleLockOff` false and `sysadminctl -screenLock immediate -password -` bring the lock back, and the lid-close lock and FileVault at boot are unaffected.
`butler.lua` also records, on both Macs, every lock, unlock, sleep, wake, display sleep, screen saver and session switch from `hs.caffeinate.watcher` in `~/.local/state/butler-access/lock-events`, and each lock's time and its cause, judged from what came in the 2 minutes before it, in `last-lock`, which an unlock removes, so `mac hosts`, `butler-keepawake status` and the machines monitor say why a Mac locked; it only listens, so it runs on `pilot` too.
It cannot keep a closed lid awake, hold system sleep off on battery or pass FileVault's password screen after a restart, which need root's `pmset -a disablesleep 1` or `fdesetup authrestart`, steps Aaron takes by hand.
Its overlay shows butler while he drives the Mac or, through spike's overlay relay, works on anything: Butler sitting in a brass porthole at the top right of the main screen, below the menu bar, head and shoulders over the rim of a circle resting on the art's bottom edge, with up to three speech bubbles beneath him, newest first, the oldest falling off at a fourth and each fading after 9 seconds, rising into view and sinking away as he fades in and out in 0.35 seconds.
It is Lua, `modules/butler-access/overlay/overlay.lua`, which Hammerspoon loads beside `butler.lua` as `~/.config/hammerspoon/butler-overlay.lua`, drawing him with `hs.canvas` in a transparent, click-through window that never becomes key, on every Space and over full-screen apps, each frame computed from the clock at 24 a second, so no process of its own runs and it needs no grant beyond Hammerspoon's.
Hammerspoon cannot set a canvas's sharing type, so unlike the JXA overlay it replaced he shows in the screenshots `mac` takes, as a 320 by 480 point corner at the top right.
An event or frame that fails to draw is logged once and skipped rather than ending the overlay.
Butler's art is `overlay/butler.svg`, whose layers `rsvg-convert` renders into separate PNGs, so his head, eyes, brows, bow tie and hands can move: he floats, breathes, sways, fidgets with his bow tie, glances about and blinks all the time, raises his brows and wiggles his bow tie as he speaks, and while `work` or `act` came in the last 20 seconds knits his brows, nods and taps the rim with gold ripples spreading from the porthole.
Its `butler-overlay show|say|act|work|rest|hide` command appends an event to `~/.local/state/butler-overlay/events`, starting the file afresh for each session, and touches `active`, which the overlay checks for every second, drawing him while it exists, so he is up only while butler drives, and stops, deleting its canvas, once he fades out on `hide` or after 90 seconds without an event, logging to `~/Library/Logs/butler-overlay.log`; `work` also touches `busy`, and `hide` leaves him up while that is under 30 seconds old, so `mac`'s `done` mid-turn never fades him out while the relay says he is working, until its `rest`.
It draws inside Hammerspoon because on `pilot` every `osascript` run of the JXA overlay before it, started by a LaunchAgent or by Hammerspoon, ended killed with SIGKILL before it drew anything, while Hammerspoon, a signed app already running, is never killed; it touches `drawing` there every second while he is on screen, which `butler-overlay status` reads, and a start that fails is logged and tried again 5 seconds later.
On `jimbo` the same module makes sshd take keys alone, authorizes butler's key the same way, and opens port 22 to `10.100.0.1` on `wg0` alone, in place of the firewall opening it to everyone.
spike's Remote Desk gateway's key, once its public half is in `modules/butler-access/remote-desk.nix`, is authorized beside butler's on both Macs and jimbo's NixOS, from `10.100.0.1` under `restrict`, its forced command printing only whether the screen is locked: on the Macs it may forward to `127.0.0.1:5900` alone, and on jimbo's NixOS it forwards nothing and its forced command pipes wayvnc's socket when asked for `vnc`, since OpenSSH refuses a unix-socket forward to any key with `permitopen`.
Windows authorizes the same key by hand with `docs/windows-remote-desk.ps1`.
It runs `wayvnc` as Aaron's user unit `butler-wayvnc` with the graphical session, on `%t/butler-wayvnc.sock` with a umask of `0077`, so only Aaron, and butler through his ssh login, reach Hyprland's screen.
Its user unit `butler-keepawake` holds an `idle:sleep` inhibitor 30 seconds at a time while `~/.local/state/butler-access/keepawake` is not `off`, on by default, and its `butler-keepawake` command sets it, or suspends the PC with `sleep`.
Its `butler-boot windows plan|go` sets the firmware's next boot to Windows Boot Manager once, or systemd-boot's `auto-windows` when the firmware has no such entry, then reboots, with the passwordless sudo every NixOS host gives `wheel`.
The PC's Windows install is set up by hand with `docs/windows-remote.ps1`, run in an administrator PowerShell after OpenSSH Server and butler's key, which installs TightVNC 2.8.90, pinned by SHA-256, as a service on `127.0.0.1:5900` alone with a random password, which it writes into TightVNC's registry itself on every run, since the MSI's silent install left none, blocks inbound VNC in Windows Firewall and registers the `butler-desktop` task.

### Butler's root

`modules/butler-root` lets the login Butler uses on a machine run commands as root, as Aaron asked on 6 Nov 2026, on for `spike` and `pilot` since he said go that afternoon and off everywhere else: a host joins its `on` list, which holds `spike`, or, for `pilot`, the employer's Mac, `butlerRoot.enable` in `modules/hosts/pilot/butler-root.nix` is true, and one `just` there applies it, one Touch ID on a Mac.
On the Macs it adds one sudoers entry, through `security.sudo.extraConfig`, letting `host.username` run butler-root's helper without a password, which runs its command as root only inside an ssh session from spike's `10.100.0.1`, logging it with `logger -t butler-root`, so Butler runs `butler-root <command>` and Aaron's own `sudo` keeps its Touch ID.
Work-managed security tooling on `pilot` may object to that entry, even limited to the helper.
On spike it gives `butler-shell` passwordless sudo and drops `NoNewPrivileges` from `butler-shell@`, whose sandbox still keeps root there off `/home`, `/etc` and the store.
jimbo's NixOS needs nothing, since wheel's sudo there asks no password already, framer gives Butler no login at all, and jimbo's Windows install is not covered: an administrator's ssh login there may already run elevated, and no helper is built.
Taking it away is the same edit back and one `just`, which removes the entry and the helper with the switch.
Whatever the machines allow, the daemon's gate decides: `root` is a critical mission item naming its machines and why, `sudo`, `su`, `doas`, `butler-root`, root PowerShell, launchd's system domain and system extensions run only where a mission lists it for that machine or Aaron approves the call, editing sudoers, making users and switching security tooling off are refused as root whatever a mission lists, and `/revoke root`, writing `butler.root.offFile`, refuses every root call at once until `/root on`.
Every root command is logged to `butler.root.logFile`, `~/.local/state/root/root.jsonl` in butler's home, and to `audit/root` in its memory, with its machine, thread, mission, command with secrets cut and exit, the desk snapshot carries today's count as `root`, and `butler-monitor` tells Aaron once when more than `rootPerHour`, 20, run in an hour, when one ran outside a mission, or when spike's sudoers changed.

### Claude Code

`modules/claude` writes the personal `CLAUDE.md`, skills and `settings.json` on every host.
Its `butler` skill lets any session read and add to butler's memory from a clone of `kranners/butler-memory` and message Aaron through `butler-notify` on spike, over SSH from other hosts.
Backlogic's plugin is on everywhere on the Linux hosts, and on the Macs nowhere but `pilot`'s backlogic checkouts.

On the Macs a `PreToolUse` hook, `pkill-guard.py`, refuses a Bash command running `pkill` or `pgrep` with an option after its pattern, because macOS takes every argument from the first pattern on as another pattern, and `pkill -f 'cat' -U $(id -u) -x` once signalled every process Aaron owned.
On the Macs `modules/cmux` appends to the personal `CLAUDE.md` a line pointing sessions that need a browser at cmux's, `cmux browser`, which holds a copy of Chromium's logins made with `cmux browser import`, since its WebKit view cannot use Chromium's profile itself, and tells them to refresh that copy before asking Aaron to sign in, and to ask in Chromium rather than cmux.
